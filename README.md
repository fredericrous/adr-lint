# adr-lint
Checks a tree against the decided code rules a linter matches exactly; marks candidate lines for reviewers (ADR-0044)

## Commands

`adr-lint coverage [-C <dir>] [--map <path>] [--json]` checks every active
governs:code constraint (from `aval --json rules --level constraint --governs
code --full`) against `map/rules.toml`; `ADR_LINT_AVAL` names the aval program.
Exit 0 none, 1 problems, 2 usage, 3 could not run.

`adr-lint check [--rule <id>] [--json] [--no-color] [--] [PATH…]` runs the
exact ast-grep rules embedded in the binary (`rules/<rule-id>/<lang>.yml`,
fixtures in `tests/rules`, `make rules`) over the named files, else
`$AMONT_FILES`, else the staged files (a path named in argv or
`$AMONT_FILES` that git lists as deleted is skipped). `--json` findings are `{path, line, col, rule, message, detail, text}`,
`text` being the source line with whitespace collapsed. It needs exactly the ast-grep version in `AST_GREP_VERSION`
(`ADR_LINT_AST_GREP` names the program). A finding is waived with
`adr-lint: allow <rule-id> -- <reason>` on its line or the line above. Exit
0 none, 1 findings, 2 usage, 3 could not run. `adr-lint help <command>`
prints a command's usage.

`adr-lint cli-probe <program> [args...]` runs the program's own command line
with stdin from /dev/null and a 10 s limit per invocation, and checks that
`-h`, `--help`, `--bogus --help` and `--version` exit 0 and that an unknown
flag exits 2 (cli.help.help-and-version). It prints one `PASS` or `FAIL` line
per check with the exit code observed. Exit 0 all passed, 1 a check failed,
2 usage, 3 the program could not be started or an invocation timed out.

`adr-lint candidates --base <ref> [--json] [--rule <id>] [--max <n>]` runs the
candidate ast-grep rules (`rules/candidates/<rule-id>/<lang>.yml`, apart from
the exact rules so `check` never reports one) over the files changed since the
merge-base of HEAD and `<ref>` and prints only the matches on added lines, each
with a stable id, for a reviewer to rule on. Candidates are not findings: exit
0 either way, 2 usage, 3 could not run. `--json` prints one versioned
`adr-lint.candidates/1` document.

A candidate rule may carry `metadata: commentExempt: same-line`, as the exact
rules do: `candidates` then drops a match with a comment on the same line after
it (`//` and `/* */`, or `#` in Python), by the same function `check` uses. The
`errors.never-swallowed` candidates use it: a Rust `let _ = <call>;` and a
`<expr>.ok();` statement, a Go `_ = <call>` or `_ = err`, and a Python
`except …: pass`, each listed only when no comment follows it on its line.

Generated files are skipped by both commands: a file is generated when, among its first 15 lines, a comment carries a standalone `@generated` tag, or starts with a generator's sentence (for example "Code generated", "Generated by", "This file is generated", "auto-generated") and says `DO NOT EDIT` (case-insensitive).

`adr-lint ruling-record --check <file>` validates a file of reviewers' ruling
records (`adr-lint.ruling/1`, JSON Lines): exit 0 valid, 1 the first bad line
named, 2 usage, 3 file unreadable. Both formats are documented in
[docs/formats.md](docs/formats.md).

`adr-lint learn [--since <YYYY-MM-DD>] --from <file>...` reports on ruling-record
files, with no model, and never writes anything: it reports, it never applies.
Records are keyed by (review, candidate) and the last one wins (file order, then
the order the files are given); `--since` drops records before that UTC date. Per
pattern id it prints the `violation` and `fine` counts and the `fine` clauses
recurring at least 5 times; a pattern with such a clause gets a
`proposal: narrow <pattern_id> or clarify <rule> body` line. A rule with at least
50 rulings of which more than 90% are `fine` is printed as `retire candidate:
<rule>`. Exit 0 report printed, 2 usage, 3 a file unreadable or invalid (named
with its line, nothing printed on stdout).

`adr-lint sync [--check] [-C <dir>]` writes clippy's `allow_attributes` and
`allow_attributes_without_reason` at `deny` into `<dir>/Cargo.toml` (`[lints.clippy]`,
or `[workspace.lints.clippy]` with `lints.workspace = true` added to each member),
keeping the file's formatting and comments; each file is written atomically
(temporary file and rename), not the run as a whole across files. A key at deny or forbid is kept; a
weaker one is reported as `path:line` and nothing is written (exit 1); a
`rust-version` below 1.81 skips Rust. `--check` writes nothing and exits 1 when
anything is missing or weaker.

`sync` also covers Python, in the repository root: it makes ruff select `PGH003`,
`PGH004` and `RUF100` and pyright set `enableTypeIgnoreComments = false` and
`reportUnnecessaryTypeIgnoreComment = "error"`. Files read: ruff's config is the
first of `.ruff.toml`, `ruff.toml`, and `pyproject.toml` with `[tool.ruff]`; pyright's
is `pyrightconfig.json`, else `[tool.pyright]` in pyproject.toml. Missing codes are
appended to `select` (or to `extend-select` when there is no `select`, so ruff's
defaults stay); a code already covered by a `select` prefix or `ALL` is left alone.
A conflict is reported as `path:line` and nothing is written (exit 1): an `ignore`
entry covering a code at least as specifically as the select that enables it, a
`per-file-ignores` entry for a covered code, or a pyright key at a weaker value. A
pyrightconfig.json with comments or trailing commas is refused (exit 3). A tool with no
config is skipped, never configured. Known limits: nested ruff configs, pyright
`executionEnvironments` and `extend` chains are not read. When both halves run the
exit status is the larger.

`sync` also covers Go, in the repository root: it makes golangci-lint enable
`nolintlint` with `require-explanation: true`, `require-specific: true` and
`allow-unused: false`. The file is the first of `.golangci.yml`, `.golangci.yaml`,
`.golangci.toml` and `.golangci.json`; only YAML with `version: "2"` is edited (anything
else is refused, exit 3), through `yaml-edit`, which keeps comments and layout.
`nolintlint` is appended to `linters.enable` (created when absent, with `linters`
itself; not needed under `default: all`), and the three settings are added under
`linters.settings.nolintlint`, only the missing keys. A conflict is reported as
`path:line` and nothing is written (exit 1): `nolintlint` in `linters.disable`, in an
`exclusions.rules` entry's `linters`, or a setting at the weaker value. `--check` also
runs `golangci-lint config verify` when golangci-lint is on PATH (a failure there
is exit 1 too), and prints
`sync: golangci-lint not installed; config not verified` when it is not. New blocks are
indented two spaces whatever the file uses.

`sync` also covers TypeScript: in the first of `eslint.config.{js,mjs,ts,mts,cts}` it
adds `adrLint` to the `@duro-app/eslint-config` import and appends
`...adrLint({ stack: [...] })` as the last element of the default-exported array, or the
last argument of `tseslint.config(...)`/`defineConfig(...)`, so its rules win over earlier
entries. `stack` lists `react` and `effect` when the import already names them; a preset the config spreads only as `...preset.map((c) => ({ ...c, files: X }))` (`X` an identifier or an array literal) becomes the scoped entry `{ name: "preset", files: X }`, copied as written. The minimum is 5.33.0 for `adrLint` and 5.38.0 for a scoped stack. The edit
points are found with ast-grep and the text is edited at those byte ranges, keeping the
file's style; the result is re-parsed and must hold exactly one `adrLint(` call. A config
that already calls it is in sync. `--check` also runs the repository's own
`node_modules/.bin/eslint --print-config` on the `.ts`/`.tsx` files git lists (not `.d.ts`; up to 20, in order, until ESLint prints a config; it says which file it used, and exits 3 naming the count when none does; a failing `git ls-files` exits 3), and
exits 1 naming any of `reportUnusedDisableDirectives`, `ban-ts-comment` (with a described
`ts-expect-error`) and the three eslint-comments rules that is not at `error`; with ESLint
not installed it prints `sync: eslint not installed; rule resolution not checked`. Refused
with exit 3: no `@duro-app/eslint-config` import, a default export that is not an array
literal or a `tseslint.config`/`defineConfig` call, an `adrLint` import under another
local name, an unreadable `@duro-app/eslint-config` range in `package.json`, and a
symlinked config, a `@duro-app/eslint-config` imported by more than one import declaration, and an `eslint.config.cjs` (a `module.exports` config is not edited; add `adrLint` by hand). `adrLint` exists from `@duro-app/eslint-config` 5.33.0: the installed
version (else the lowest the `package.json` range admits; `workspace:` passes; `>` admits the next patch; a prerelease is below its release; a `||` union, a pair of bounds, a hyphen range, `x` and `*` are refused with exit 3; no installed or declared version is refused with exit 3) below
that is refused with exit 1 and nothing is written, also under `--check`.

## Install

```sh
brew install fredericrous/tap/adr-lint
```

Or download `adr-lint-<version>-<target>.tar.gz` from the
[releases](https://github.com/fredericrous/adr-lint/releases) (targets:
`aarch64-apple-darwin`, `x86_64-apple-darwin`, `x86_64-unknown-linux-gnu`,
`aarch64-unknown-linux-gnu`), check it against `SHA256SUMS`, and put the
`adr-lint` binary on your `PATH`.

`adr-lint check` and `candidates` need ast-grep at the version in
`AST_GREP_VERSION` (`brew install ast-grep`, or its releases page).

## ESLint preset

`npm/eslint-config/` is the npm package `@aval-adr/eslint-config`: `adrLint()`
and `adrLintTyped()` flat-config factories carrying the TypeScript lint settings
that match the decided rules exactly. It is versioned with this crate and
published on each `v*` tag; see its README.

## Releasing

Bump `version` in `Cargo.toml` and add a `## v<version>` section to
`CHANGELOG.md` in a pull request, and merge it. Then push a `v<version>` tag:
the release workflow checks the tag against `Cargo.toml`, builds the four
targets, publishes the GitHub release with `SHA256SUMS`, and, when the
`PUBLISH_TAP` variable is `true`, rewrites `Formula/adr-lint.rb` in
`fredericrous/homebrew-tap` with `scripts/bump-tap.py` and checks that brew
installs it. The seed formula is `packaging/homebrew/adr-lint.rb`.
