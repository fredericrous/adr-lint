# Changelog

## Unreleased

- `adr-lint cli-probe <program> [args...]` checks a CLI black-box: `-h`, `--help`, `--bogus --help` and `--version` must exit 0 and an unknown flag must exit 2, each run with stdin from /dev/null and a 10 s limit. One `PASS`/`FAIL` line per check; exit 0 all pass, 1 a failure, 2 usage, 3 the program could not be started or timed out.

## v0.10.0

- `adr-lint sync` now syncs Go too: golangci-lint `nolintlint` enabled with `require-explanation: true`, `require-specific: true` and `allow-unused: false`, in `.golangci.yml` or `.golangci.yaml` (version 2, edited losslessly with the new `yaml-edit` dependency; `nolintlint` in `linters.disable` or in an exclusion rule, or a weaker setting, is a conflict and nothing is written; a TOML or JSON config is refused). `--check` also runs `golangci-lint config verify` when it is installed.
- `adr-lint sync` now syncs TypeScript too: it adds `adrLint` to the `@duro-app/eslint-config` import of `eslint.config.{js,mjs,ts,mts,cts}` (an `eslint.config.cjs` is refused with exit 3: `module.exports` is not edited) and appends `...adrLint({ stack: [...] })` as the last element of the default-exported array (or the last argument of `tseslint.config(...)`/`defineConfig(...)`), with `stack` naming `react` and `effect` when the import does. Edit points come from ast-grep, the edit is text, and the result is re-parsed before it is written. `--check` also runs the repository's `node_modules/.bin/eslint --print-config`, trying up to 20 listed `.ts`/`.tsx` files until ESLint prints a config (it names the file used, and on failure gives ESLint's last error), and reports a required setting not at `error`; without ESLint installed it says so; it exits 3 when no file works or `git ls-files` fails. More than one import declaration from `@duro-app/eslint-config`, no installed or declared version, and a range with `||`, a space, a hyphen range, `x` or `*` are refused with exit 3; `>5.32.0` reads as 5.32.1 and a prerelease of 5.33.0 as below it. A `@duro-app/eslint-config` older than 5.33.0 (installed, else the lowest the `package.json` range admits) is refused with exit 1, writing nothing; an unreadable range or an aliased `adrLint` import is refused with exit 3. A config with no such import, a default export of another shape, or a symlink is refused (exit 3).

## v0.9.0

- `adr-lint sync` now syncs Python too: ruff `PGH003`, `PGH004` and `RUF100` selected, and pyright `enableTypeIgnoreComments = false` and `reportUnnecessaryTypeIgnoreComment = "error"`, in `.ruff.toml`, `ruff.toml`, `pyproject.toml` or `pyrightconfig.json` (format-preserving; an ignore of a covered code or a weaker pyright value is a conflict and nothing is written; a tool with no config is skipped). Known limits: nested ruff configs, pyright `executionEnvironments` and `extend` chains.

## v0.8.1

- Fix: a waiver comment is read only with the file's own comment leader (`#` in Python, `//` or `/*` elsewhere), so a `#` inside a Rust string literal is no longer a waiver.

## v0.8.0

- New `adr-lint sync [--check] [-C <dir>]`: writes clippy's `allow_attributes` and
  `allow_attributes_without_reason` at `deny` into Cargo.toml (workspace-aware,
  format-preserving, each file written atomically by temporary file and rename). Rust is the only language synced so far.

## v0.7.0

- New candidate patterns for `errors.never-swallowed`: a Rust `let _ =` of a call
  and a Rust `.ok();` statement, a Go blank assignment of a call or an error, a
  Python `except …: pass`. `candidates` now honours `metadata.commentExempt`
  (the function `check` uses), so these are listed only with no comment on the same line.
- `check` and `candidates` skip generated files: a comment among the first 15
  lines carries a standalone `@generated` tag, or starts with a generator's
  sentence (for example "Code generated", "Generated by") and says `DO NOT EDIT`. A
  comment that merely discusses the markers does not count.

## v0.6.0

- New npm package `@aval-adr/eslint-config` (`npm/eslint-config/`): `adrLint` and
  `adrLintTyped` flat-config factories for the decided code rules a linter
  matches exactly, published by the release workflow when `PUBLISH_NPM` is `true`.

## v0.5.0

- `amont.pack` declares the `adr-lint check` row, for amont and for amont-agent's write-time hook,
  at severity `warn`.
- `adr-lint check --json` findings carry `text`: the source line with
  whitespace trimmed and collapsed, normalized as `candidates` ids are.
- `check` skips a named or `$AMONT_FILES` path that is missing and that git
  reports as deleted, instead of exiting 3; other missing paths still exit 3.

## v0.4.0

- `adr-lint candidates --head <ref>` measures the change from the merge-base
  of <ref> and `--base` to <ref>, reading every changed file's text from
  <ref>'s git objects instead of the working tree, so a commit that is not
  checked out can be listed. The JSON `head` is then the sha of <ref>.
- A changed symlink is no longer scanned in either mode; before, the
  working-tree run followed a symlink to a source file.

## v0.3.0

- BREAKING: candidate ids now also hash the 1-based column of the match, so
  two matches on one line (two `.unwrap()` calls) get distinct ids. This
  changes every id.
- The failures.expected-vs-defect candidate patterns no longer match in test
  files nor inside a Rust `mod` carrying `#[cfg(test)]`.
- A file named `tests.rs` (Rust's out-of-line test module) now counts as a
  test file, for failures.expected-vs-defect and also for tests.no-real-waits,
  whose sleeps in `tests.rs` are now candidates.
- docs/formats.md: `adr-lint learn` is described as not yet shipped, and
  renaming a pattern id is documented as a breaking change within `/1`.

## v0.2.0

- Candidate ids now include the occurrence number of the line among the
  file's added identical lines, so identical added lines get distinct ids.
  This changes every id; acceptable before any consumer exists.
- Paths in all output use `/` separators.
- `adr-lint candidates --json` prints a versioned `adr-lint.candidates/1`
  document `{format, base, head, candidates, overflow}` instead of a bare array.
- docs/formats.md documents the candidates document and the
  `adr-lint.ruling/1` ruling-record JSONL.
- `adr-lint ruling-record --check <file>` validates a ruling-record file.

## v0.1.0

The first release (decisions ADR-0044).


- `adr-lint coverage`: checks every active governs:code constraint against `map/rules.toml`.
- `adr-lint check`: runs the exact ast-grep rules embedded in the binary.
- `adr-lint candidates`: prints candidate matches on added lines for reviewers.
